# 06. Shortest Paths

A **shortest-path problem** involves finding a path between two vertices such that the total path cost is minimized.

**How do we find the shortest or least expensive route between two vertices?**

The cost may represent:
- Distance between locations.
- Travel time.
- Network latency.
- Transportation cost.
- Any numerical value assigned to edges.

For an unweighted graph, the shortest path is generally the path containing the fewest edges.

For a weighted graph, the shortest path is the path having the minimum total edge weight.

## 1. Path Cost

Before understanding shortest-path algorithms, we need to understand how the cost of a path is calculated.

Consider a weighted graph:

```text
A ── 4 ── B
│         │
2         3
│         │
C ── 1 ── D
```

There are different routes from A to D.

**Route 1:**

\[
A\rightarrow B\rightarrow D
\]

Total cost:

\[
4+3=7
\]

**Route 2:**

\[
A\rightarrow C\rightarrow D
\]

Total cost:

\[
2+1=3
\]

Therefore, the shortest path is:

\[
\boxed{A\rightarrow C\rightarrow D}
\]

With a total cost of 3.

## 2. Shortest Path in Unweighted Graphs — BFS

For an unweighted graph, every edge is treated as having equal cost.

Therefore, minimizing the total path cost is equivalent to minimizing the number of edges.

**Breadth-First Search (BFS)** can find shortest paths from a source vertex to all reachable vertices in an unweighted graph.

For example:

```text
       B ─── D
      /       \
     A         F
      \       /
       C ─── E
```

Starting from A, BFS explores vertices level by level.

The first time a vertex is discovered, its shortest distance from A has been found.

\[
\text{Time Complexity}=O(V+E)
\]

BFS is particularly useful when:
- The graph is unweighted.
- All edges have equal cost.
- We need shortest paths based on the number of edges.

## 3. Dijkstra's Algorithm

**Dijkstra's Algorithm** finds the shortest paths from a source vertex to other reachable vertices in a weighted graph with non-negative edge weights.

It follows a greedy approach.

At each step, it selects the unvisited vertex with the smallest known tentative distance and updates the distances of its neighbors.

### How It Works

1. Assign distance 0 to the source vertex.
2. Assign infinity to all other vertices.
3. Select the unvisited vertex with the smallest tentative distance.
4. Examine its neighboring vertices.
5. Update their distances if a shorter route is found.
6. Mark the selected vertex as processed.
7. Repeat until all reachable vertices have been processed or the destination is finalized.

### Relaxation

The central operation in Dijkstra's Algorithm is called **relaxation**.

Suppose we have an edge:

\[
u\rightarrow v
\]

with weight \(w(u,v)\).

We check whether reaching \(v\) through \(u\) produces a shorter distance.

\[
\boxed{d(v)=\min(d(v),d(u)+w(u,v))}
\]

If the new route is shorter, we update the distance.

### Example

Consider:

```text
A ──4── B
│       │
2       1
│       │
C ──3── D
```

Starting from A:

| Vertex | Shortest Distance |
|---|---:|
| A | 0 |
| B | 4 |
| C | 2 |
| D | 5 |

The shortest route from A to D is:

\[
A\rightarrow B\rightarrow D
\]

with total cost:

\[
4+1=5
\]

### Complexity

Using an adjacency list and a binary min-heap:

\[
O((V+E)\log V)
\]

**Important limitation:** Dijkstra's Algorithm does not work correctly in general when negative-weight edges are present.

## 4. Bellman-Ford Algorithm

**Bellman-Ford** finds shortest paths from a single source vertex, even when the graph contains negative-weight edges.

Unlike Dijkstra's Algorithm, it does not require all edge weights to be non-negative.

### How It Works

Bellman-Ford repeatedly relaxes every edge in the graph.

For a graph containing \(V\) vertices, it performs up to:

\[
V-1
\]

complete relaxation rounds.

Why \(V-1\)?

A shortest simple path can contain at most \(V-1\) edges because it cannot repeat vertices.

After these rounds, one additional pass is performed to check for negative-weight cycles.

### Relaxation

For every edge \(u\rightarrow v\):

\[
\boxed{d(v)=\min(d(v),d(u)+w(u,v))}
\]

The update is performed whenever the newly calculated distance is smaller.

### Negative-Weight Cycle Detection

A **negative-weight cycle** is a cycle whose total edge weight is negative.

For example:

\[
A\rightarrow B\rightarrow C\rightarrow A
\]

If its total weight is:

\[
2+(-5)+1=-2
\]

Repeatedly traversing this cycle can keep decreasing the path cost.

Therefore, a finite shortest-path distance does not exist for vertices reachable through such a cycle.

If any distance can still be reduced during the additional relaxation pass, a negative-weight cycle reachable from the source exists.

### Complexity

\[
\boxed{O(VE)}
\]

**Best suited for:**
- Graphs containing negative-weight edges.
- Detecting reachable negative-weight cycles.
- Single-source shortest-path problems.

## 5. Floyd-Warshall Algorithm

So far, BFS, Dijkstra, and Bellman-Ford have focused on finding shortest paths from one source vertex.

But what if we want shortest paths between **every pair of vertices**?

This is where the **Floyd-Warshall Algorithm** becomes useful.

It is a dynamic programming algorithm that calculates all-pairs shortest paths.

### Core Idea

The algorithm gradually considers each vertex as an intermediate vertex in a path.

For every pair of vertices \(i\) and \(j\), it checks whether travelling through an intermediate vertex \(k\) produces a shorter path.

The recurrence relation is:

\[
\boxed{
D^{(k)}[i][j]
=
\min\left(
D^{(k-1)}[i][j],
D^{(k-1)}[i][k]+D^{(k-1)}[k][j]
\right)
}
\]

In simpler terms:

- Keep the existing shortest distance from \(i\) to \(j\).
- Compare it with the distance from \(i\) to \(k\), followed by \(k\) to \(j\).
- Store whichever is smaller.

### Complexity

Time complexity:

\[
\boxed{O(V^3)}
\]

Space complexity:

\[
\boxed{O(V^2)}
\]

**Important:** Floyd-Warshall supports negative-weight edges but cannot produce meaningful finite shortest paths for pairs affected by negative-weight cycles. Such cycles can be detected by checking for negative diagonal entries in the final distance matrix.

## 6. Comparing Shortest-Path Algorithms

| Algorithm | Problem Type | Negative Edges | Time Complexity |
|---|---|---|---|
| BFS | Single-source, unweighted | Not applicable | \(O(V+E)\) |
| Dijkstra | Single-source, weighted | No | \(O((V+E)\log V)\)* |
| Bellman-Ford | Single-source, weighted | Yes | \(O(VE)\) |
| Floyd-Warshall | All-pairs | Yes | \(O(V^3)\) |

\*Dijkstra's complexity assumes an adjacency list with a binary min-heap.

## 7. Shortest Path vs. Minimum Spanning Tree

These two concepts are often confused because both involve minimizing edge costs.

However, they solve different problems.

**Shortest Path:**

Finds the minimum-cost route between specified vertices.

**Minimum Spanning Tree (MST):**

Finds a set of edges connecting all vertices in a connected, undirected, weighted graph while minimizing the total edge weight.

| Feature | Shortest Path | Minimum Spanning Tree |
|---|---|---|
| Objective | Minimize route cost | Minimize total network cost |
| Focus | Route between vertices | Connect all vertices |
| Output | Shortest route(s) | A spanning tree |
| Common Algorithms | Dijkstra, Bellman-Ford | Prim, Kruskal |

For example, a navigation system may use shortest-path algorithms to find a route between two locations, whereas designing a low-cost network connecting several locations is an MST problem.

## Why Shortest Paths Matter

Shortest-path algorithms are fundamental to many real-world systems:

- **Navigation:** Finding routes between locations.
- **Networking:** Finding low-cost routes through communication networks.
- **Transportation:** Optimizing travel and delivery routes.
- **Social Networks:** Measuring separation between individuals.
- **Infrastructure:** Analyzing connectivity and transportation costs.

Understanding these algorithms also prepares us for more advanced topics such as network flow, graph optimization, and routing algorithms.
