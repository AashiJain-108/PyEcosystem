# 04. Graph Representation

Graph representation refers to the different ways of storing vertices and edges of a graph in computer memory.

A graph is mathematically represented as:

\[
G=(V,E)
\]

Where:
- \(V\) represents the set of vertices.
- \(E\) represents the set of edges.

However, computers need a suitable data structure to store and access these elements.

The most common graph representations are:

1. Adjacency Matrix
2. Adjacency List
3. Edge List
4. Incidence Matrix

Let's consider the following undirected graph:

\[
V=\{A,B,C,D\}
\]

\[
E=\{\{A,B\},\{A,C\},\{B,C\},\{C,D\}\}
\]

## 1. Adjacency Matrix

An **adjacency matrix** represents a graph using a two-dimensional matrix.

Each row and column represents a vertex.

The matrix entry indicates whether an edge exists between the corresponding pair of vertices.

For an unweighted graph:

\[
A_{ij}=
\begin{cases}
1 & \text{if an edge exists between }i\text{ and }j\\
0 & \text{otherwise}
\end{cases}
\]

For our example:

| | A | B | C | D |
|---|---:|---:|---:|---:|
| **A** | 0 | 1 | 1 | 0 |
| **B** | 1 | 0 | 1 | 0 |
| **C** | 1 | 1 | 0 | 1 |
| **D** | 0 | 0 | 1 | 0 |

Notice:
- A is connected to B and C.
- B is connected to A and C.
- C is connected to A, B, and D.
- D is connected only to C.

### Important Characteristics

- For an undirected graph, the adjacency matrix is symmetric.
- For a simple graph, diagonal entries are zero because self-loops are not allowed.
- For a weighted graph, entries can store edge weights instead of just 0 and 1.
- For a directed graph, the matrix is not necessarily symmetric.

### Complexity

| Operation | Complexity |
|---|---|
| Check whether an edge exists | \(O(1)\) |
| Find all neighbors of a vertex | \(O(V)\) |
| Add an edge | \(O(1)\) |
| Space required | \(O(V^2)\) |

**Best suited for:** Dense graphs, where many possible edges actually exist.

## 2. Adjacency List

An **adjacency list** stores each vertex along with a collection of its neighboring vertices.

Instead of storing every possible vertex-to-vertex relationship, it stores only the existing connections.

For our example:

```text
A → B, C
B → A, C
C → A, B, D
D → C
```

Each vertex maintains a list of its adjacent vertices.

For a weighted graph, each neighbor entry can also store the corresponding edge weight.

For example:

```text
A → (B, 5), (C, 10)
B → (A, 5)
C → (A, 10)
```

### Important Characteristics

- Stores only existing edges.
- Efficient for exploring the neighbors of a vertex.
- Requires less memory for sparse graphs.
- In an undirected graph, every edge generally appears in the adjacency lists of both endpoints.

### Complexity

| Operation | Complexity |
|---|---|
| Check whether an edge exists | \(O(\deg(v))\) |
| Find all neighbors of a vertex | \(O(\deg(v))\) |
| Add an edge | \(O(1)\) amortized |
| Space required | \(O(V+E)\) |

*Note: Edge lookup depends on the data structure used for each neighbor collection. A hash-based representation can provide different lookup performance.*

**Best suited for:** Sparse graphs and graph traversal algorithms.

## 3. Edge List

An **edge list** represents a graph as a collection of its edges.

Each entry records the two endpoints of an edge.

For our example:

```python
edges = [
    ("A", "B"),
    ("A", "C"),
    ("B", "C"),
    ("C", "D")
]
```

For a weighted graph, each edge can also contain its weight:

```python
weighted_edges = [
    ("A", "B", 5),
    ("A", "C", 10),
    ("B", "C", 3),
    ("C", "D", 7)
]
```

### Important Characteristics

- Simple and straightforward representation.
- Stores only the existing edges.
- Useful for processing or iterating through all edges.
- Finding all neighbors of a vertex generally requires scanning the edge collection.

### Complexity

| Operation | Complexity |
|---|---|
| Iterate through all edges | \(O(E)\) |
| Check whether an edge exists | \(O(E)\) |
| Find neighbors of a vertex | \(O(E)\) |
| Space required | \(O(E)\), plus vertex storage if needed |

**Best suited for:** Edge-based algorithms, input/output formats, and algorithms such as Kruskal's Minimum Spanning Tree algorithm.

## 4. Incidence Matrix

An **incidence matrix** represents the relationship between vertices and edges.

Unlike an adjacency matrix, where both rows and columns represent vertices, an incidence matrix uses:

- Rows for vertices.
- Columns for edges.

Consider our example:

\[
e_1=(A,B)
\]

\[
e_2=(A,C)
\]

\[
e_3=(B,C)
\]

\[
e_4=(C,D)
\]

The incidence matrix is:

| | \(e_1\) | \(e_2\) | \(e_3\) | \(e_4\) |
|---|---:|---:|---:|---:|
| **A** | 1 | 1 | 0 | 0 |
| **B** | 1 | 0 | 1 | 0 |
| **C** | 0 | 1 | 1 | 1 |
| **D** | 0 | 0 | 0 | 1 |

An entry is:

$$
M_{ij} = \begin{cases} 
1 & \text{if vertex } v_i \text{ is incident to edge } e_j \\ 
0 & \text{otherwise} 
\end{cases}
$$

### Important Characteristics

- Rows represent vertices.
- Columns represent edges.
- Each column of an ordinary undirected graph without self-loops contains two 1s.
- Directed incidence matrices commonly use \(-1\) and \(+1\) to distinguish edge direction, depending on the chosen convention.

**Best suited for:** Mathematical graph analysis, network-flow formulations, and problems involving relationships between vertices and edges.

## 5. Comparing Graph Representations

All four representations can describe the same graph, but they organize information differently.

| Representation | What it stores | Space Complexity |
|---|---|---|
| Adjacency Matrix | Vertex-to-vertex connections | \(O(V^2)\) |
| Adjacency List | Neighbors of each vertex | \(O(V+E)\) |
| Edge List | Collection of edges | \(O(E)\) |
| Incidence Matrix | Vertex-to-edge relationships | \(O(VE)\) |

### Which One Should We Use?

| Situation | Suitable Representation |
|---|---|
| Dense graph | Adjacency Matrix |
| Sparse graph | Adjacency List |
| Frequently process all edges | Edge List |
| Study vertex-edge relationships mathematically | Incidence Matrix |

There is no universally best representation. The choice depends on the graph structure and the operations we need to perform.

## 6. Sparse vs. Dense Graphs

Understanding sparse and dense graphs helps explain why different graph representations exist.

**Sparse Graph:**

A graph with relatively few edges compared with the maximum possible number of edges.

**Dense Graph:**

A graph with a relatively large number of edges compared with the maximum possible number of edges.

For example:

- A road network with relatively few direct connections between intersections may be sparse.
- A small network where almost every vertex connects to every other vertex may be dense.

This distinction matters because an adjacency matrix always allocates space for every possible vertex pair, even when most edges do not exist.

An adjacency list stores only the existing connections, making it more memory-efficient for sparse graphs.

---

## Quick Recap

| Representation | Main Idea |
|---|---|
| Adjacency Matrix | Stores whether pairs of vertices are connected |
| Adjacency List | Stores the neighbors of each vertex |
| Edge List | Stores the collection of edges |
| Incidence Matrix | Stores which vertices belong to which edges |

**Key takeaway:** A graph is a mathematical structure, while an adjacency matrix, adjacency list, edge list, and incidence matrix are different ways to represent that structure in memory.

The same graph can be stored using different representations without changing its underlying topology.
